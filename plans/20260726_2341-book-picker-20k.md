# OMR “Bài” picker — không dùng `<select>` 20k (SOLID / DRY / KISS / DevOps)

**Ngày giờ:** 2026-07-26 23:41 · **Trạng thái:** ✅ XONG — report: [../reports/20260726_2345-book-picker-20k.md](../reports/20260726_2345-book-picker-20k.md)

## Câu hỏi
Dropdown `Bài` (OmrViewer) với 20.000 option — dùng được không?

## Trả lời thẳng
**Không.** Với ~20k bài, `<select>` + `books.map(…)` là anti-pattern UX + perf.

| Góc | Vấn đề |
|---|---|
| **UX** | Không tìm được bài; cuộn 20k dòng; mobile chết |
| **Perf (browser)** | 20k `<option>` trong DOM ≈ chậm mount, layout, memory |
| **Perf (network)** | Dump cả catalog mỗi lần mở OMR Viewer |
| **Ops** | Không paginate / không cache / không quan sát được load |

## Tư duy (đúng với SOLID · DRY · KISS · DevOps)

### KISS trước
Đừng “framework hóa” catalog. Rule đơn giản: **không bao giờ render toàn bộ catalog thành control chọn một**.
- Input tìm kiếm → hiện **≤ N kết quả** (N=15–20) → chọn → `open(slug)`.
- Đó là đủ cho MVP 20k nếu metadata nhẹ.

### SOLID
- **S**: `OmrViewer` = sửa Inter trên 1 book đang mở. **Chọn book** = responsibility khác → `BookPicker`.
- **O**: nguồn catalog đổi được (index.json → API `?q=` → sau này SQLite FTS) mà không đụng logic edit.
- **D**: UI phụ thuộc *interface* “search scores → open slug”, không phụ thuộc “list all into `<select>`”.

### DRY
Thư viện đã có ô **Tìm theo tên**. Picker OMR **tái dùng cùng mô hình tìm kiếm** (và cùng catalog), không invent dropdown thứ hai chứa full list.

### DevOps
- API: `GET /api/books?q=&limit=20` — server-side filter, không dump 20k.
- Client: không giữ 20k node DOM; có thể giữ cache metadata nếu cần.
- Observability: log `books_count`, `search_q`, `open_slug` (sau).
- Scale path đã có trong library plan: FTS5 + worker — picker phải **giả định** catalog lớn từ ngày đầu.

## Plan (phiên này)
1. API `GET /api/books?q=&limit=` (default limit 20 khi có `q`, hoặc luôn cap khi list).
2. Thay `<select class="omr-book">` bằng **BookPicker** (typeahead).
3. Report + SSOT.

## Check
- Gõ vài ký tự → ≤20 gợi ý; chọn → mở đúng `.omr`.
- Không còn `books.map` full list vào `<option>`.
