# Báo cáo khả thi: Port Audiveris GUI sang Web

**Thời điểm**: 2026-07-26 01:56
**Trạng thái**: 🟢 Nghiên cứu xong · chốt chiến lược A

## Tóm tắt

Port toàn bộ editor Swing sang web trong 1 lần là bất khả thi (~289 file UI, Java2D, không có API). Nhưng vòng giá trị cốt lõi — **nhận dạng → sửa → nghe** — khả thi qua kiến trúc **web mỏng + JVM edit-service** tái dùng engine/model sẵn có.

## Bằng chứng từ codebase

- **Engine headless được**: `Main.java` bỏ qua `Application.launch(MainGui.class)` khi `-batch`; `Book.export`/`transcribe` chỉ kiểm `OMR.gui == null`. Đã verify batch tạo `.omr` + `.mxl`.
- **Model sửa được, độc lập widget (một phần)**: `sig/ui/UITask*` (`AdditionTask`, `RemovalTask`, `LinkTask`…) mutate `SIGraph` (`addVertex`/edge) không cần widget; `TaskHistory` lo undo/redo.
- **Nhưng khóa Swing**: `InterController` (2690 dòng) chạy `@UIThread`, dùng selection service/DnD/dialog; domain (`Inter`, `Sheet`, `Book`) import `java.awt.*` và cả `javax.swing` rải rác; `Inter` biết `ui.symbol.MusicFont`. → Chạy trên **JVM server OK**, nhưng phải bọc/no-op phần UI của controller.
- **Không có REST/servlet** nào trong cây Java. Có `CLI -run <RunClass>` để viết script batch tùy biến — hữu ích làm điểm bám cho server.

## Cấu trúc `.omr` (đã giải nén kiểm chứng)

```
book.xml                     # metadata, steps đã chạy, page/system/part
sheet#1/BINARY.png           # ảnh nhị phân (nền để overlay)
sheet#1/sheet#1.xml          # 42k dòng: glyphs, inters, relations
```

Mỗi Inter (ví dụ thực tế):
```xml
<barline width="3" shape="THIN_BARLINE" glyph="1" grade="0.79" ctx-grade="0.79" staff="1" id="2">
  <bounds x="1118" y="378" w="3" h="93"/>
</barline>
```
Thống kê sheet#1: 857 `<bounds>`, 831 `<relation>`, 130 `<head>`, 127 `<stem>`, 91 `<word>`, 65 `<sentence>`, 41 `<barline>`… → đủ dữ liệu dựng overlay có ý nghĩa.

## So với câu hỏi trước (Capella Scan / "nhắc vị trí sai")

Đúng tinh thần Capella: sửa chỗ máy nhận sai rồi cho nhận lại. Trong Audiveris = sửa Inter/Relation (P3–P4) rồi re-run step (P7). Web hoá đúng vòng này chính là mục tiêu port.

## Rủi ro lớn nhất & giảm thiểu

1. **`InterController` phụ thuộc UI-thread/selection** → P3: tạo lớp façade gọi thẳng `UITask` performDo, hoặc stub các dịch vụ selection; test bằng so khớp XML.
2. **Toạ độ overlay lệch** → P1: dùng đúng ảnh BINARY và cùng hệ toạ độ pixel trong `<bounds>`.
3. **Hiệu năng ~857 hộp** → chuyển canvas nếu DOM chậm.
